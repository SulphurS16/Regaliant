# Regaliant, from a game executable to a displayed frame

On 8 October 2026 the repository began with an earlier native port's core. By 26 November the Linux branch could load a Demon's Souls save, draw the Nexus at native 4K, and distinguish how many new images reached the presentation queue from how many frames the game itself produced. Between those points lay two different engineering jobs. The first was to give an existing executable the machine it expects. The second was to find which parts of that machine could run ahead, overlap or reuse previous work while the game still saw the right bytes in the right order.

1. [The machine the game expects](01-first-principles.md) follows one guest pointer from a CPU instruction to a GPU result.
2. [From boot to a presented frame](02-architecture.md) follows the implementation, including the structures that carry state between subsystems.
3. [How the shared runtime took shape](03-history.md) traces the Windows project from first boot through renderer design and release engineering.
4. [Bringing that runtime to Linux](04-linux.md) traces the fork through OS integration, memory tracking, pipeline reuse, interpolation and measured performance.
5. [What remains open](05-open-problems.md) distinguishes observed faults, tested explanations, workarounds and gaps in coverage.
6. [Glossary](06-glossary.md) decodes the vocabulary used in source comments, commit messages and profiles.

**Scope.** This is a reading of the local history ending at `linux-port` commit `0ee206e` on 26 November 2026. It contains 1,055 reachable commits. The local Windows `main` tip is `1acbe83`, the merge base is `6285013`, and `main..linux-port` contains 62 commits, including merges. Windows changes dated after the fork reached Linux only where the histories overlap. The fork README uses the published branch name `linux-support`. The source checkout used for the chronicle remains at `21a0f16`. The next commit, including its minimum-LOD changes, was read directly from Git. Short hashes throughout can be inspected locally with `git show HASH`. Measurements belong to the cited sessions. This chronicle involved source and history inspection only.

The [project README](../../README.md) distinguishes fork status from upstream claims. The [changelog](../../CHANGELOG.md) describes Windows releases from the player's perspective. The [Linux guide](../linux.md) gives the corresponding fork procedures and defaults.

## Reading with the source open

Start with the worked examples in part 1. Then follow a single frame in part 2 with two source windows open, one for the guest-facing code and one for the device-facing code. Read the five dated chapters in order after that. Doing it in this order makes a change such as “take pages after arming” intelligible before the history asks you to judge whether it solved the right bug.
